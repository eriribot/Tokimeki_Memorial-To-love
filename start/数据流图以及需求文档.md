# start 玩家登记与每存档 Persona 合同

## 当前实现合同（2026-08-13）

`start` 负责标题页、赛菲的蓝色天鹅绒房间入口、梨子入学登记事件和主角登记。新游戏先由赛菲询问是否接受性格画像：“否”直接进入梨子递交入学登记表的事件；“是”进入由内置六阶段自适应提示词引导的画像访谈，结束后也进入同一个梨子事件。两条分支汇合后，姓名、生日、血型、外貌、性格及最终确认都在登记流程完成。登记草稿在最终确认前只存在于组件本地；只有最终“确认登记”才写入当前新游戏已经取得的独立 `saveUuid`，资料随后不可编辑。

| 项目 | 当前合同 |
| --- | --- |
| 主角身份 | User 是主角；性别固定为男性，界面只读展示 |
| 必填字段 | 姓、名、生日月日、血型、外貌、性格 |
| 新游戏入口 | 先显示赛菲蓝色房间的“是 / 否”画像邀请；“否”不调用模型，直接进入梨子入学登记事件 |
| 赛菲画像 | “是”进入由内置六阶段自适应提示词引导的性格画像；阶段按信息缺口追问，不等于固定六道题，真实模型遵循情况仍需实机验收 |
| 字段权威 | 赛菲只可回填 `personality`；姓名、外貌、生日、血型及其他资料仍由玩家亲自填写和确认 |
| 文本规则 | NFKC；普通空白折叠；控制字符拒绝；外貌和性格各最多 160 个 Unicode 字符 |
| 性格边界 | 只表示非关键语气与反应倾向，不授权模型替玩家决定关键行动、对白、路线或状态 |
| 存档 | 两条入口分支汇合后，只有登记页最终确认才创建并保存完整 `PlayerProfile`；`GameSnapshot` schema v4 严格保存，v3 及更早明确拒绝，不迁移 |
| 酒馆 Persona | 赛菲画像不接管 Persona；登记完成后的主线生成不创建、不改写真实 Persona，只在请求期间临时接管 `{{user}}` 与 Persona Description，结束后恢复原 Persona |

## 权威数据流

```text
startNewSession()
  ├─ beginNewTavernAutosaveIdentity() → 独立 saveUuid
  └─ gameStore.resetGameState() → screen=registration

PlayerRegistration（本地草稿）
  └─ 赛菲蓝色房间：是否接受性格画像？
       ├─ 否 → 梨子入学登记事件（不调用模型）
       └─ 是 → VelvetRoom 内置六阶段自适应画像
            ├─ TavernHelper.generateRaw()
            ├─ ordered_prompts = 内置 system + 组件内存历史 + 本轮回答
            ├─ 只解析并回填 personality；report 只在画像界面展示
            └─ 画像完成 → 梨子入学登记事件

梨子入学登记事件（两条分支汇合）
  └─ 姓名 → 生日 → 血型 → 外貌 → 性格 → 最终确认
       └─ completeNewSessionRegistration()
            ├─ createPlayerProfile() → 规范化与严格校验
            ├─ playerStore.completeRegistration() → 唯一 PlayerProfile
            ├─ gameStore.completeRegistration() → registration → game
            └─ gameSaveApi.save() → 登记完成后立即保存

PlayerProfile
  ├─ GameSnapshot.player.profile（schema v4）
  ├─ CharacterArchivePanel（性别、生日、血型、外貌、性格）
  ├─ window.render_game_to_text().playerProfile
  └─ GenerateStoryActRequest.playerProfile（请求发起前冻结）
       ├─ <tolove_player_profile> 版本化 JSON 资料块
       ├─ /persona-set mode=temp：本次生成的 {{user}} 临时切换为 displayName
       ├─ overrides.persona_description 或一次性 depth-0 system 注入
       ├─ 生成窗口内清空宿主 Persona Description，阻止 Author's Note / At Depth 旁路
       ├─ <tolove_player_identity_guard>：存档身份是唯一权威
       ├─ 本次 WORLDINFO_ENTRIES_LOADED 清空 personaLore
       ├─ success / error / cancel finally：恢复原 Persona 名称与描述
       └─ GalStoryGenerationContext 保存资料签名、注入版本和承载方式
```

## 赛菲画像生成边界

1. 邀请页的“是 / 否”和选择“是”后的第一道正式问题都由本地 UI 提供；选择“否”不会触发生成。
2. 画像运行时不 `import`、`fetch` 或解析 `Aiforpersonality/Izumi 用户画像模式3 (1).json`。该文件只作为六阶段访谈设计的离线参考，也不进入运行时 bundle。
3. 画像不采用酒馆当前启用的 preset，不调用 `TavernHelper.generate({ preset_name: 'in_use' })`。每轮调用 `TavernHelper.generateRaw()`，通过 `ordered_prompts` 明确提交内置 system prompt、当前组件的内存历史和本轮玩家回答。
4. 多轮历史随 `VelvetRoom` 组件存在，用完即弃；不写酒馆楼层、世界书、`GameSnapshot`、`PlayerProfile` 或自动存档。
5. 内置 system prompt 使用六阶段自适应访谈：日常决策、故事体验、文风重心、人际情感、压力与价值、边界复核。信息不足或矛盾时继续追问，不把六阶段实现成固定六道题。
6. 完成结果必须包含通过本地校验的 `<personality>` 与只读 `<report>`；出现 `<appearance>` 会显式失败。父级只接收 `personality`，姓名、外貌及其他登记字段仍由玩家填写。
7. 无论拒绝画像还是接受并完成画像，都先汇入梨子入学登记事件；在登记页最终确认之前不会保存玩家资料。

登记完成后的主线生成服务不得在异步读取世界书、等待模型或重试期间重新读取 `playerStore`。历史楼层重新生成前必须用当前存档完整资料重新计算签名；与原楼层不一致时拒绝生成，防止 A/B 存档串档。

## Persona 覆盖规则

本节描述登记完成后的主线剧情生成，不属于赛菲的 `generateRaw()` 画像链；赛菲画像不接管当前酒馆 preset 或真实 Persona。

1. 生成前保存当前 Persona ID、展开后的用户名和 Persona Description；缺少可恢复 Persona 时可见失败，不开始生成。
2. 使用酒馆原生 `/persona-set mode=temp` 让预设的 `{{user}}` 在本次请求中展开为存档 `displayName`，但不改写 Persona 记录。
3. 当前预设启用了 `personaDescription` 占位项：完整资料块通过 `overrides.persona_description` 覆盖，depth-0 只注入短身份护栏。
4. 占位项未启用：Persona Description 覆盖为空，完整资料块与护栏合并为一次性、`should_scan: false` 的 depth-0 system 注入。
5. 生成窗口内把 `powerUserSettings.persona_description` 暂时置空，阻止原描述从 Author's Note 或 At Depth 位置旁路进入；随后按原值恢复。
6. 本次剧情世界书扫描删除 `personaLore` 副本，保留 Chat Lore、Character Lore、Global Lore 和项目选择的剧情/人物条目。
7. 成功、异常和取消都在 `finally` 恢复原 Persona 并停止一次性扫描钩子；剧情生成使用单请求互斥锁。
8. 用户若在生成期间主动切换到另一个 Persona，恢复逻辑不强行切回；这些操作不创建、改名、删除、重绑或持久改写真实 Persona。

## 验收边界

- 本地自动测试验证：v4 字段、危险结构转义、A/B 签名隔离、Persona 承载分支、Persona Lore 过滤、钩子清理和生成互斥。
- Prompt Preview 显示有效资料块、签名、承载方式、身份护栏及屏蔽来源。
- 真实酒馆仍需人工用 Prompt Itemization/Prompt Inspector 检查 Persona 的 None、Prompt Manager、Author's Note、At Depth 四种位置，并确认生成前后真实 Persona 与世界书配置不变。
- v1 不含头像上传、身高体重结构化字段、资料编辑、旧存档迁移或真实 Persona 同步。
