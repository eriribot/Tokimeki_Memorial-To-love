0. 先看一句话结论
==================

Second Base 的约会强，不是因为它有更多成人文本，而是因为它把一次约会做成了一个连续的临时状态：

  取得联系方式
    -> 邀约并写入日历
    -> 到点赴约
    -> 地点活动池
    -> 角色即时反应改变约会分数
    -> 达到门槛后角色主动提出继续
    -> 晚间或追加活动
    -> 最终关系结算、取消/失约后果、手机日历记录

当前 DatingModule 更接近：

  邀约
    -> 预先抽一次 awkward/good/great
    -> 播放 main GAL
    -> 播放 return GAL
    -> 把两次固定增量相加

本方案的核心改动只有一句话：

  把“开场预抽质量 + 两段固定结算”改成“约会内累积 dateScore + 阶段门槛 + 角色主动续摊”。

6. 方案：逐项把原作概念改成校园版本
=====================================

6.1 预约和 AP
-------------

[PLAN]

    phone invitation:
        require contact
        monthly quota = 4
        AP cost = 0
        accepted or declined both consume one quota

    face-to-face invitation:
        AP cost = 1 on attempt       # 推荐默认，防止免费刷失败
        phone quota unchanged

    formal date on the scheduled day:
        beginWholeDayActivity('dating')
        consume one daily activity slot
        internal date actions consume no extra AP

这意味着 AP 的职责是“开始一个社会行动/占用一天”，不是给约会中的每句话收费。

6.2 约会状态
-------------

[PLAN] 伪代码，不是 TypeScript 实现：

    DateRun {
        appointmentId
        invitationChannel       // phone | faceToFace
        dateScore               // 本场临时分数，建议内部 0..100
        phase                   // main | continue | return
        continuationOffered
        continuationAccepted
        selectedActivities[]
        giftId                  // 没有送礼时为空
        paymentOutcome
        relationshipDelta
        outcomeBand             // cool | steady | warm | excellent
    }

    begin date:
        dateScore = neutral
        phase = main

    choose activity:
        local rule settles score, friendship, romance, money, time
        character reaction is selected from the saved director plan

    after main phase:
        if dateScore >= continuationThreshold:
            character asks whether to continue
            player chooses continue or end
        else:
            go to return

    finish:
        convert outcomeBand to authoritative friendship/romance deltas
        archive the plan, choices, resources and accepted text

[KEEP] friendship/romance 仍是权威关系轴。
[CHANGE] `dateScore` 只描述这一场约会，不成为第三条长期好感轴。

6.3 地点活动池
---------------

[PLAN] 首个可玩切片：公园、河堤、商店街；每个地点 2-3 个活动。

    DateActivity {
        id
        locationTag
        duration
        moneyCost
        baseScore
        friendshipDelta
        romanceDelta
        matchTags
        mismatchTags
        oncePerDate
        nextPhaseTag
    }

    scoreDelta = baseScore + locationFit + profileMatch + riskResult

角色 profile 使用校园语义，例如：安静、爱热闹、务实、贪吃、浪漫、怕尴尬。
不要把原作的 `sub`, `sexperience`, 成人服装或成人性格标签搬过来。

6.4 购物和送礼
---------------

原作商场代码只做：

    money spent -> score gained

校园版本拆成两个不同动作：

    shopTogether:
        一起逛商店街/看文具/吃点心
        影响时间、dateScore 和角色反应

    giveGift:
        item has cost, tags, novelty, target preferences
        one gift per date
        local rule decides liked / awkward / inappropriate
        result writes to dateScore and friendship/romance

送礼不应成为“越贵越好”的通用按钮；昂贵但不合适的礼物可以比普通但合适的礼物更差。

当前设计文档把礼物列为首版暂不纳入，因此建议：

  - 首版先做 shopTogether。
  - 送礼作为第二阶段，在角色偏好数据准备好后加入。

6.5 AI 和本地规则的边界
-----------------------

[PLAN]

    directorPlan = local deterministic data
        - chosen location
        - activity pool
        - score effects
        - character tags
        - continuation permission
        - payment/gift result
        - allowed facts and names

    AI receives directorPlan
    AI writes only the current GAL text
    parser rejects text that invents AP, money, relationship values or events

[KEEP] 当前 `datingStoryGeneration` 的 parser/fallback 和“AI 不结算状态”边界。
[CHANGE] 给 AI 的计划从“quality + 两段通用选项”变成“当前阶段已确定的活动结果和角色反应”。

这里玩家在意的是：前面做得好不好，决定她会不会愿意延长约会。

7.2 校园项目的同类场景（示例数字，不是最终数值）
--------------------------------------------------

    预约 Riko 在河堤见面
    -> main 阶段出现：谈社团 / 买饮料 / 拍照
    -> 选择“谈社团”
       本地结算：dateScore +10，friendship +2
       Riko 的 profile 匹配“熟悉话题”，反应为放松
    -> 选择“买饮料”
       若资金足够：dateScore +5，触发口味反应
    -> dateScore 达到继续门槛
    -> Riko 主动问“要不要再走一段”
    -> 玩家接受后进入 riverbank continuation
    -> 回程选择“认真约下次见面”
       本地结算：romance +3
    -> GAL 只负责把这些已确定结果写成自然对白

如果第一步选择了明显不合 Riko profile 的行动，可能仍然完成约会，但不会出现继续邀约。
这就是“选择改变过程”，而不是“选择只改变结尾数字”。

9. 首个可玩切片和验收方式
==========================

首个切片只验证：

  - 3 名角色
  - 3 个地点
  - 每地点 2-3 个活动
  - 1 条电话邀约路径
  - 1 条当面邀约路径
  - main -> 可选 continue -> return
  - 一次成功和一次失败结果
  - 读档、重生成不会重新抽签

验收时要能观察到：

  1. 不同活动会改变角色反应或是否得到继续机会。
  2. 约会内部活动不额外扣 AP。
  3. 电话额度、当面 AP、金钱和关系结算由本地规则控制。
  4. AI 重生成只改变文字，不改变导演计划和结算。
  5. 约会回忆记录活动、结果和已采纳正文。
