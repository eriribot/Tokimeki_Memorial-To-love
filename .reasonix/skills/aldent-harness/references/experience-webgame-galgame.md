# 经验：Webgame 选项行动与 Galgame 渲染

## Use when

选项点击会触发剧情生成、状态结算、数据库写入或宿主消息；模型输出包含规划、正文、总结或数值。

## Four phases

- 选项展示：只呈现候选动作。
- 选项选择：记录用户意图。
- 行动结算：由前端、宿主、数据库或明确规则结算权威状态。
- 正文渲染：只消费允许进入 Galgame 的正文协议。

## Invariants

- 规划、规则解释和调试文本不进入正文楼层或渲染器。
- 前端已经结算的值不交给模型二次改算。
- 重生成复用当前阶段保存的 prompt/context。
- UI 成功不等于数据库、宿主楼层或插件链成功。

## Evidence

- 日志区分选择、结算、正文生成和状态写入。
- 渲染器只接收正文协议内容。
- 截图、控制台、宿主消息和数据库日志互相对应。
- 隔离阶段证明禁用链路未触发，普通阶段证明要求的真实链路已触发。
